# TEMPO

[앱 열기](https://minjaedy.github.io/cale/) · [GitHub](https://github.com/minjaedy/cale)

아이폰용 루틴·식단·코칭 앱입니다. 프런트엔드는 GitHub Pages, 인증·기록은 Firebase Spark, 패스키·푸시·예약 알림은 Cloudflare Workers와 D1을 사용합니다.

## 사용

1. Safari에서 앱을 열고 **공유 → 홈 화면에 추가**를 선택합니다.
2. 일반 사용자 또는 트레이너를 선택해 Google로 로그인합니다.
3. 사용자는 **코칭 → 트레이너 연결 → 초대 코드**를 전달하고, 트레이너는 **회원 연결**에 입력합니다. 코드는 24시간 동안 한 번만 사용할 수 있습니다.
4. 사용자가 식단을 등록하면 연결된 트레이너에게, 트레이너가 코멘트를 등록하면 사용자에게 알림이 전송됩니다.
5. **코칭 → 알림·설정 → 알림 켜기**를 각 기기에서 선택합니다. 아이폰은 iOS 16.4 이상 홈 화면 앱에서 알림을 허용해야 합니다.
6. 트레이너는 **Face ID 등록**에서 Google 재인증 후 패스키를 등록합니다. 다음 로그인부터 **Face ID 로그인**을 사용할 수 있습니다. 실제 인증 수단은 기기 설정에 따라 Face ID 또는 기기 암호가 됩니다.

처음 로그인하면 이름과 개인 캘린더를 등록하고 **기본 루틴** 시간표로 이동합니다. 오른쪽 위 **기본 루틴**에서 같은 시간표를 다시 열 수 있습니다. 요일의 ＋ 또는 **루틴 추가**로 설정하고, 기존 일정을 눌러 수정합니다. 날짜 이동으로 최근 1년의 지난 날짜를 조회할 수 있습니다. 기본 반복 루틴 한 벌을 날짜에 맞춰 표시하므로 매일 복사본을 저장하지 않습니다. 완료 체크·식단·코멘트·체중은 해당 날짜별로 365일 보관한 뒤 저장소에서도 삭제합니다. 월–일 반복 요일을 선택하고 시간을 설정할 수 있습니다. 기존 소유자는 검증된 기존 Google 계정으로 로그인할 때 원래 루틴을 가져오며, 이미 저장된 캘린더를 덮어쓰지 않습니다. 트레이너는 회원 관리 화면만 사용합니다. 코멘트에는 8종 TEMPO 이모티콘을 단독 또는 글과 함께 붙일 수 있습니다.

## 식단과 체중

- 신체 정보와 활동량으로 성인 칼로리 목표를 계산하거나 직접 입력합니다. 주간 체중은 주당 한 번 기록하고 수정할 수 있으며, 최신 체중과 수정한 프로필로 현재 목표를 다시 계산합니다. 등록된 식단의 목표·칼로리 값은 이후 DB나 체중 변경으로 바꾸지 않습니다.
- 음식과 양을 입력하면 이번 식사와 등록 후 하루 합계를 표시합니다. 예: `김치찌개 1인분, 밥 한 공기`, `카페라떼 350ml`. 음식 검색·빠른 입력·총칼로리 수정도 지원합니다.
- 기본 음식·원재료·가공식품 7,507개는 약 1 MB의 정적 `food-catalog.json`이며 GitHub Pages에서 제공합니다. Firebase DB에 중복 저장하지 않습니다. 출처는 [식약처 식품영양성분 DB](https://various.foodsafetykorea.go.kr/nutrient/general/down/historyList.do), 2026-10-12 수집입니다. 음식 DB는 2026-08-28판, 원재료·제품은 각 원본 행의 공개 영양정보입니다. `scripts/build-food-catalog.py`에 열 매핑과 선정·환산 기준이 있습니다.
- 100g/100ml 영양값에 입력량을 곱합니다. 개·공기·잔·인분은 표시된 기준량으로 가정하며, 조리법과 브랜드에 따라 다릅니다. 정확한 브랜드·중량 또는 포장지 값을 우선하세요. 찾지 못한 음식은 `미계산`으로 표시합니다. 모든 제품을 포함하거나 AI가 임의 추정하는 방식은 아닙니다.
- **음식 추가**에서 음식명·기준량·단위·칼로리를 등록하면 공용 DB에 바로 반영됩니다. 모든 사용자에게 `사용자 등록`으로 표시되며, 기본 식약처 자료와 이름이 겹치면 기본 자료를 우선합니다. 직접 등록한 음식만 수정·삭제할 수 있습니다. 이름 변경은 새 등록으로 처리합니다. 다른 제품은 브랜드·제품명을 포함하세요. 공개 정보에는 계정 UID·이메일·개인 식단을 넣지 않습니다.
- Mifflin–St Jeor와 활동 계수에 목표 체중 조정(감량 −300, 증량 +200 kcal)을 적용한 추정치입니다. 자동 계산은 19–78세 성인 범위이며, 개별 식단은 직접 설정할 수 있습니다.

하루·주간 보기의 모든 일정에 개별 완료 체크가 있습니다. 날짜·일정 ID별로 저장하며, 일정 달성률에 반영합니다. 기존 습관 체크 기록은 유지하고, 운동·공부·취침 습관과 연결된 일정의 체크도 함께 반영합니다.

루틴 시작 알림은 등록된 모든 반복 일정에 적용됩니다. 예약 서버가 매분 확인하므로 약 1분의 오차와 푸시 서비스의 지연이 발생할 수 있습니다. 루틴 수정은 Firebase 저장 후 예약 서버에 반영됩니다. 인터넷 연결이 필요합니다.

## 앱 아이콘 배지

홈 화면·Dock·작업표시줄에 미확인 알림 수를 표시합니다. 아이폰은 iOS 16.4 이상 홈 화면 앱, Mac은 macOS Sonoma 14 이상 Safari의 **Dock에 추가** 또는 지원하는 Chrome·Edge 설치 앱, Windows는 Chrome·Edge 설치 앱에서 사용합니다. OS의 앱 알림·배지 표시 설정도 켜져 있어야 합니다. 브라우저 탭이나 지원하지 않는 환경에서는 기존 앱 안 알림을 사용합니다.

앱이 닫혀 있어도 Service Worker가 푸시 수신 시 숫자를 갱신합니다. 식단·코멘트 읽음 처리와 알림 클릭·닫기는 해당 배지를 지우며, 루틴 화면을 열면 수신한 루틴 알림을 확인 처리합니다. 로그아웃·계정 전환 때 이전 계정의 배지를 지웁니다. 체험판은 실제 앱 배지를 변경하지 않습니다. 배지용으로는 기기에 알림 식별자만 최대 2,000개·365일 보관하며, 본문이나 인증 토큰은 저장하지 않습니다. Firebase/D1에 배지 기록을 추가하지 않습니다.

지원 기준: [WebKit 홈 화면 배지](https://webkit.org/blog/14112/badging-for-home-screen-web-apps/), [Safari 17의 Mac 웹 앱](https://webkit.org/blog/14445/webkit-features-in-safari-17-0/), [Microsoft Edge 배지](https://learn.microsoft.com/en-us/microsoft-edge/progressive-web-apps/how-to/notifications-badges). OS 아이콘의 실제 표시는 해당 기기에서 확인해야 합니다.

## 배포 구조

| 역할 | 서비스 |
| --- | --- |
| 앱 | `https://minjaedy.github.io/cale/` |
| 웹 배포 | main push → GitHub Actions → Pages |
| Google·패스키 세션 | Firebase Authentication / cale-b2c40 |
| 기록·코칭 | Firebase Realtime Database |
| 패스키·Web Push·매분 예약 | `https://tempo-coach.couple-private-push.workers.dev` |
| 패스키 공개키·알림 구독·전송 대기 | TEMPO 전용 D1 / tempo-coach |

다른 앱의 서버나 DB를 공유하지 않습니다. Firebase Hosting 주소는 GitHub Pages로 이동합니다. Firebase authDomain은 Google 인증 처리용입니다. Blaze 전환 없이 구성했습니다. 각 서비스의 무료 사용량 한도는 적용됩니다.

## 저장·권한

- 개인 일정과 날짜별 기록: `/tempo/users/{uid}`. 해당 계정만 읽고 쓸 수 있습니다.
- 완료 체크: `/tempo/users/{uid}/days/{date}/completed/{eventId}`. 각 필드만 동기화합니다.
- 코칭: `/tempo/coaching`. 초대를 수락한 연결 관계만 식단·코멘트를 공유합니다. 연결 해제 후 트레이너의 접근·새 알림 전송은 차단됩니다.
- 식단·코멘트의 덮어쓰기는 막고, 사용자는 자신이 등록한 식단을 삭제할 수 있습니다. 부모 식단을 먼저 삭제해 새 코멘트를 차단한 뒤 연결된 코멘트·이모티콘과 전송 대기 알림도 제거합니다. 다른 사용자·트레이너는 삭제할 수 없습니다. 일일 기록·식단·코멘트·이모티콘·체중은 모두 기록 날짜 기준 365일 보관합니다. 반복 루틴·프로필·연결은 유지합니다. 공용 음식 정보도 일일 기록과 별도로 유지합니다.
- 기존 `/users/{uid}` 규칙은 유지합니다. 일정 삭제·개별 기록 수정은 허용하고 날짜별 기록 전체 삭제는 막습니다.
- 일반 서비스 클레임은 필요한 코칭 경로만 읽습니다. 초대 목록은 만료 시각순으로 최대 100개씩 조회하며 실제 삭제는 만료된 코드만 허용합니다. 별도 정리 클레임은 특정 UID의 날짜별 기록·피드·읽음 상태를 읽고 만료된 항목만 삭제할 수 있습니다. 보관 중인 기록·반복 루틴·프로필은 변경할 수 없습니다. 루틴 예약 동기화는 요청 사용자의 ID 토큰으로 읽습니다.
- 패스키는 서버에서 일회용 challenge, origin, RP ID, 사용자 확인과 서명을 검증합니다. Firebase의 동일 UID 세션으로 이어집니다.
- 비밀키는 Cloudflare Secrets에만 보관합니다. Firebase 웹 설정은 공개 설정입니다. Admin JSON·개인키·토큰을 GitHub에 넣지 마세요.
- 발송 전에 연결을 재확인하고, 중복 방지·재시도·만료된 구독 정리를 수행합니다. 발송 메타데이터는 7일, 읽음 상태는 365일 후 정리합니다. 매분 서버 작업에서 계정을 순차 점검하므로 앱을 닫아도 만료 기록을 삭제합니다. 소규모 이용 시 계정당 약 한 시간 간격이며, 이용량·오류 재시도에 따라 지연될 수 있습니다. 기존 오프라인 쓰기도 만료된 일일 기록을 복원하지 않도록 거릅니다.
- 계정별 임시 저장·전송 대기열을 분리합니다. 브라우저 데이터를 지우면 미전송 기록은 사라질 수 있습니다. 기록 화면에서 JSON 백업을 받을 수 있습니다. 관리자·프로젝트 삭제까지 막는 보장은 아닙니다.

## 공용 음식 누적

- 공용 음식은 최대 20,000개를 지원하며, 이후에는 용량과 검색 구조 확장이 필요합니다.
- 기본 자료는 main의 `food-catalog.json`, 새 공용 자료는 [food-data 브랜치](https://github.com/minjaedy/cale/tree/food-data)의 `community-foods.json`에 보관합니다. Firebase 저장 공간을 사용하지 않습니다.
- 앱은 등록 응답부터 즉시 사용하고, 다른 열린 앱은 다음 데이터 확인(최대 약 60초) 또는 다시 열 때 반영합니다. GitHub Actions는 5분 간격으로 누적 저장합니다. GitHub 스케줄 대기 때문에 실제 실행은 늦어질 수 있습니다. 같은 작업은 서버 예약 누락에 대비해 정리 작업도 다시 실행합니다. 음식 추가만으로 앱 전체를 재배포하지 않습니다.
- Cloudflare D1은 미반영 변경을 보관합니다. GitHub 커밋 검증 후 음식 본문은 D1에서 지우고 작은 수정 권한·버전 정보만 남깁니다. 등록자별 최대 200개, 미반영 변경은 최대 500개까지 받으며, 장애 중에는 기존 변경을 잃지 않고 재시도합니다.
- Actions의 짧은 OIDC 토큰을 저장소 ID·소유자 ID·main·foods.yml에 한정해 검증합니다. GitHub 쓰기는 해당 작업의 임시 GITHUB_TOKEN만 사용합니다. 사용자 브라우저나 Cloudflare에 장기 GitHub 토큰을 넣지 않습니다.
- 등록 정보는 공개되며 사용자 입력 열량은 검증된 공인 값이 아닙니다. 앱에서 삭제해도 GitHub의 이전 커밋 이력에는 남을 수 있으므로 개인정보를 입력하지 마세요. 기존 개인 식단·체중·코멘트는 공개하지 않습니다.

## 앱 업데이트

빌드마다 콘텐츠 해시를 만들고 `version.json`을 확인합니다. 앱 복귀·온라인 전환·60초 간격으로 새 버전을 확인하고, 입력·모달·작성 초안·전송 대기가 없을 때 자동 적용합니다. 적용 직전 다시 확인하며, 작성 중이면 배너로 대기합니다. 서비스 워커는 오프라인 안내와 아이콘만 캐시합니다.

## 개발·검증

Node 22.13 이상과 Java 21을 사용합니다.

```sh
npm ci
npm ci --prefix server
npm run dev
npm test
npm run test:rules
npm run test:server
npm run build
npm run build --prefix server
```

로컬 주소는 `http://127.0.0.1:8765/`입니다. 인증 서버는 GitHub origin만 허용하므로 로그인·패스키 최종 확인은 배포 주소에서 합니다. 브라우저 패스키 모듈은 SimpleWebAuthn 14.0.0의 배포용 번들이며 라이선스는 `PASSKEY-LICENSE.md`에 있습니다.

```sh
npx --prefix server wrangler d1 execute tempo-coach --remote --file server/schema.sql
npm run deploy:rules
npm run deploy:server
git push origin main
```

서버 초기 구성은 `server/wrangler.jsonc`, `server/schema.sql`을 사용합니다. Secrets: `FIREBASE_ACCOUNT`, `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`. 재배포 때 기존 VAPID 키와 Firebase 서비스 계정 키를 유지합니다. 키를 변경하면 기존 알림 구독의 재등록이 필요할 수 있습니다.

검증에는 RTDB 에뮬레이터 권한 테스트, 실제 서명을 사용하는 WebAuthn 테스트, 알림 중복·재시도·해제·만료·시간대 테스트를 포함합니다. 배포 서버에서 임시 계정으로 식단·코멘트·루틴 설정·패스키 서명→Firebase UID 연결을 확인한 뒤 테스트 자료를 정리했습니다. 실제 아이폰 Face ID 화면과 잠금화면 푸시 수신은 해당 기기에서 등록·권한 허용 후 확인해야 합니다.

## 체험판

[체험용 TEMPO](https://minjaedy.github.io/cale/demo.html)는 운영 앱과 같은 화면을 로그인 없이 확인하는 샘플입니다. [임시 검토 주소](https://cale-b2c40--tempo-preview-81qv2dk8.web.app/)도 2026-10-19까지 사용할 수 있습니다. 운영 앱은 기존 GitHub Pages 주소를 유지합니다.

체험판은 로그인 없이 회원·트레이너 화면, 기본 루틴 시간표, 완료 체크, 주간 체중, 식단 계산·등록·삭제, 이모티콘과 코멘트를 확인합니다. 상단에서 회원/트레이너를 전환하거나 처음 등록 화면을 열 수 있습니다. 새로 열면 샘플로 초기화합니다. 개인 캘린더와 별도 키를 사용하고 Firebase 및 공용 음식 서버에 쓰지 않습니다. 실제 Face ID와 잠금화면 알림은 본 앱에서 등록·권한 허용 후 사용합니다.

`node scripts/preview.mjs`는 모의 화면 의존성만 `qa/preview-public`에 준비합니다. `firebase hosting:channel:deploy tempo-preview --expires 7d --no-authorized-domains --project cale-b2c40 --config qa/firebase-preview.json`으로 미리보기 채널만 갱신합니다. CSP로 외부 DB 연결을 차단하며, 운영 Hosting 리디렉션과 GitHub Pages를 바꾸지 않습니다.
